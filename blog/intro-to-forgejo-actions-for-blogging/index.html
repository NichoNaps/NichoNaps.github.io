The other question is where to pair it? In forgejo you can pair your runner at 4 different scopes to limit which repos can access the runner. You can find the settings to add a runner and view what runners available whenever you see Actions -> Runners in the left nav.

Scope Access Description Settings Under
repo USER/REPO Usable only on that specific repo Repo Settings
user USER/* Usable by all of the user's repos User Settings
org ORG/* Usable by all of the org's repos Org Settings
global */* Usable by all repos Site Administration

Mention:

Also a quick recommendation, I had installed my forgejo instance with sqlite as the database and it worked flawless for my own personal commiting and occasionally viewing the website usage. However, the moment I started using runners and trying to use the website at the same time, it would freeze up. I love sqlites but its more designed for integrating into apps instead of websites so it lacks support for in this case, handling parallel requests which leads to the database locking up because the running runner and database are both fighting for the database.

So unless you plan on never using actions I highly recommend using another backend like postgress. To make matters worse, Forgejo also doesn't have an official way to migrate from sqlite to postgress so it can be hard to fix after the fact. Luckly I didn't have too many repos at the time so I just fixed it by manually recreating it from scratch.

Calling Workflow Dispatch API

The api we need to call for triggering a workflow to run is:

POST /repos/{owner}/{repo}/actions/workflows/{workflowname}/dispatches

https://YOUR_FORGEJO_HOST/api/swagger#/repository/DispatchWorkflow

My recommendation would be to test out the api endoint in swagger because it shows off a lot of details about the sorts of arguments you can pass, lets you test the api in browser, and generates the curl command you need to run in the workflow.

Docs how to call api endpoints: https://forgejo.org/docs/latest/user/api-usage/ Reference for apis you can call are generated by swagger https://YOUR_FORGEJO_HOST/api/swagger

Up in the top right of swagger is an Authorize button you can use to authenticate. You can test using your forgejo account or you can use the tokenAuthorizationHeaderToken option which lets you test the exact same token you'd be using in the workflow. Just remember to enter it in the format token MY_TOKEN.

Aside

You can login and upload containers to registries with podman or docker. However, both of those tools rely on a daemon in the background which, while normally fine, when running in a ci workflow to build the container it is running within a container itself so then you'd have to deal with docker in docker which requires a privileged container and so on making it a huge hassle. We can skip all that by using a dedicated tool for registries, in this case skopeo. This is a great intro to skopeo if you have seen it before.
