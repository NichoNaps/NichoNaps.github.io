I noticed something odd when setting up a graph in Grafana for RAM usage. What is the difference between an SI or IEC byte unit? How could the 8 bits of a byte be represented so differently?

 > 
 > **TLDR:** SI prefixes (kilo, mega, giga) are powers of 1000. IEC prefixes (kibi, mebi, gibi) are powers of 1024. Lots of software historically displayed SI prefixes but computed the prefix with powers of 1024. This can occasionally lead to confusion because the historic way has stuck around so you never know for sure if SI prefixes are actually powers of 1000.

## The Crimes Against SI Prefixes

The problem lies in unit prefixes.

As a quick refresher, In the [SI system we have what are called prefixes](https://en.wikipedia.org/wiki/Metric_prefix). These little prefixes make writing larger (or smaller) numbers easier. kilo $= 1000$, mega $= 1000^2 = 1,000,000$, giga $= 1000^3 = 1,000,000,000$ etc. So I can for example say I walked $1$ kilometer instead of having to say I walked $1000$ meters.

To make units even easier to write there are even official shorter versions of these same prefixes so you can write "km" instead of the full name, "kilometer".  

The beauty of this system is that in addition to these units being short to write, they can be used intuitively across many different units while signifying the same jump in size like 1 kilogram $= 1000$ grams or 1 kilowatt $= 1000$ watts. 

So, naturally, one would think that if a file is listed as 1 kilobyte, that means your file is definitely $1000$ bytes right? **No**

Historically, many things in software were measured in multiples of base 2 but, and here's the fun part, incorrectly reported using the SI prefixes. So often you may see reported byte sizes where 1 kilobyte $= 1024$ bytes, 1 megabyte $= 1024^2 = 1,048,576$ and so on. For the full history of binary prefixes [see](https://en.wikipedia.org/wiki/Timeline_of_binary_prefixes).

## IEC Binary Prefixes to the Rescue (kind of)

In 1999, binary prefixes were introduced by the [IEC](https://en.wikipedia.org/wiki/International_Electrotechnical_Commission) as a way to make it clear to the reader that they are using binary prefixing ( $1024^n$ i.e. it is a multiple of 2 ) instead of SI prefixing ( $1000^n$ i.e. it is a multiple of base 10). You can tell the two prefixes apart by the added "i" to the end of each short prefix. They also changed the long form of the prefixes so for example instead of "kilo" it uses "kibi".

|SI Prefix Value|SI Prefix|IEC Prefix Value|IEC Prefix|
|---------------|---------|----------------|----------|
|$1000$|(k) kilo|$1024$|(Ki) kibi|
|$1000^2$|(M) mega|$1024^2$|(Mi) mebi|
|$1000^3$|(G) giga|$1024^3$|(Gi) gibi|
|$1000^4$|(T) tera|$1024^4$|(Ti) tebi|
|For the full table [see](https://en.wikipedia.org/wiki/Binary_prefix).||||

We can see these prefixes in the graphs generated by Grafana. The IEC graph on the right uses "GiB" on the y axis while the SI graph on the left uses "GB" on the y axis.
![Pasted image 20260915202450.png](../../Attachments/Pasted%20image%2020260915202450.png)

At this point you're probably wondering when you should use one prefix over the other. The answer is that it entirely depends on the context. Storage, for example, is often written in SI. This is probably because that way a gig contains fewer bytes so they can write a bigger number on the box. On the other hand, RAM is best written in IEC because it's physically addressed in binary so it's capacity is inherently a power of 2. In other words its a lot nicer to to write 8 GiB instead of 8.589934592 GB.

## The Messy Reality

The problem is that this IEC binary prefix was added too late, so a lot of software and entire industries continue to show byte sizes with SI prefixes even though they compute the prefix like an IEC prefix. While this causes occasional confusion, this old way of writing prefixes just isn't going anywhere anytime soon.

To demonstrate how this can be confusing, I'll use two hard drives I recently purchased that were advertised as 8 TB (correctly using SI prefixes). Let's explore how file managers on different operating systems default to displaying the size of these drives.

### Windows

If we were to plug those drives into a [Windows PC](https://learn.microsoft.com/en-us/answers/questions/3311884/si-prefixes-for-information-sizes-and-proper-symbo) in 2026 (27 years after 1999), we would feel scammed because File Explorer would report the drive as only having 7.28 TB. This is because Windows File Explorer still shows SI prefixes even though it computes the size like an IEC prefix. So from the consumer's perspective they would see $8 \ \text{TB} = 7.28 \ \text{TB}$ which makes no sense. [This confusion helped lead to a class action lawsuit over SanDisk USBs in 2020.](https://www.courthousenews.com/wp-content/uploads/2020/01/flashdrives.pdf)

### MacOS

If we plugged those drives into MacOS, Finder would report them as 8 TB because MacOS switched over to properly computing SI prefixes for file sizes all the way back in [2009](https://en.wikipedia.org/wiki/Mac_OS_X_Snow_Leopard).

### TrueNAS Scale

![Pasted image 20260915210600.png](../../Attachments/Pasted%20image%2020260915210600.png)

If we plug those drives into TrueNAS (shown above) it instead shows 7.28 TiB. This is still correct because $8 \ \text{TB} \approx 7.28 \ \text{TiB}$. We can check that by multiplying 8 by the value of the SI prefix and then dividing by the value of the IEC prefix (TB = $1000^4$, TiB = $1024^4$ ).

$\frac{8\cdot1000^{4}\ }{1024^{4}\ }= 7.2759576141 \ \text{TiB}$

## Linux Desktops

On Linux there is a wide variety of desktops and associated default file managers you could possibly view those drives with. From the ones I've checked they all display the prefixes correctly (unlike Windows) but some default to showing IEC prefixes (7.28 TiB) and others to SI prefixes (8 TB) like MacOS.

|Desktop|File Manager|Default Prefixes|
|-------|------------|----------------|
|Plasma|Dolphin|IEC|
|Xfce|Thunar|IEC|
|LXDE|PCManFM|IEC|
|Gnome|Nautilus|SI|
|Cosmic|Cosmic Files|SI|
|Linux Mint|Nemo|SI|

## Conclusion!

So how did 8 bits get counted so differently? historically and often still today, prefixes for bytes are reported using SI prefixes (multiples of 1000) even though they are computed using multiples of 1024. In 1999 the IEC published a dedicated binary prefix to help correct the misuse of the SI prefix but the old way has stuck around. Thus, even 27 years later you still can't be sure an SI prefix is a multiple of 1000 and consumers are understandably so confused that they sue over it.
